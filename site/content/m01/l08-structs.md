# Структуры и методы

В Go нет классов, наследования и конструкторов в привычном смысле. Вместо них три простых инструмента: **структуры** (данные), **методы** (функции, привязанные к типу) и **встраивание** (композиция вместо наследования). Из них собирается всё: модели данных, сервисы, репозитории, хендлеры HTTP. Если ты пришёл из TypeScript с классами, придётся перестроить привычки, и этот урок про то, как.

Для бэкенда структуры это прежде всего модели: `User`, `Order`, `Expense`. Они ездят в JSON и обратно через теги, лежат в мапах как ключи и значения, передаются между слоями приложения. А методы с правильным получателем решают, изменится ли объект или его копия, и реализует ли тип нужный интерфейс.

На собесе из этой темы спрашивают: value или pointer receiver и как выбрать, что такое method set и почему `T` не реализует интерфейс, а `*T` реализует, чем встраивание отличается от наследования, какие структуры сравнимы, зачем пустая структура. В конце урока мини-проект модуля: учёт расходов с хранением в JSON, где всё это пригодится вместе.

## Объявление и создание

```go
type User struct {
	ID    int64
	Name  string
	Email string
	admin bool // с маленькой буквы: не видно за пределами пакета
}
```

Регистр первой буквы поля работает так же, как для функций: `Name` экспортировано (видно из других пакетов и для `encoding/json`), `admin` нет.

Способы создать значение:

```go
var u1 User                          // нулевое значение: все поля нулевые
u2 := User{ID: 1, Name: "Аня"}        // именованные поля, остальные нулевые
u3 := User{2, "Петя", "p@x.ru", false} // позиционно: все поля по порядку
p := &User{Name: "Гоша"}              // указатель на новую структуру
q := new(User)                        // то же, что &User{}
```

Позиционную форму в рабочем коде почти не используют: добавишь поле в середину, и все литералы сломаются или, хуже, тихо перепутают значения одного типа. `go vet` предупреждает о позиционных литералах для структур из чужих пакетов.

Доступ к полям через указатель не требует `(*p).Name`: Go разыменовывает сам.

```go
p := &User{Name: "Гоша"}
p.Name = "Георгий" // то же, что (*p).Name = "Георгий"
```

Анонимные структуры удобны для одноразовых данных: табличные тесты, разбор JSON с парой полей, ответ хендлера.

```go
resp := struct {
	OK    bool   `json:"ok"`
	Error string `json:"error,omitempty"`
}{OK: true}
```

## Структура это значение

Как и массив, структура копируется целиком при присваивании и передаче в функцию.

```go
a := User{Name: "Аня"}
b := a
b.Name = "Боря"
fmt.Println(a.Name) // Аня
```

Если в структуре есть слайс, мапа или указатель, копируется только **заголовок** или указатель, а данные остаются общими. Копия структуры поверхностная:

```go
type Team struct {
	Name    string
	Members []string
}

t1 := Team{Name: "A", Members: []string{"Аня"}}
t2 := t1
t2.Members[0] = "Боря"
fmt.Println(t1.Members[0]) // Боря: слайс общий
```

### Сравнимость

Структуры можно сравнивать через `==`, если **все** поля сравнимы. Сравнение поэлементное.

```go
type Point struct{ X, Y int }
fmt.Println(Point{1, 2} == Point{1, 2}) // true

type Tagged struct{ Tags []string }
a, b := Tagged{}, Tagged{}
_ = a == b // ошибка компиляции: struct containing []string cannot be compared
```

Сравнимую структуру можно сделать ключом мапы, это идиоматичный составной ключ: `map[Point]bool`. Учти, что указатели сравниваются по адресу, а не по содержимому:

```go
type T struct{ P *int }
x, y := 1, 1
fmt.Println(T{&x} == T{&y}) // false: разные адреса
```

Для глубокого сравнения несравнимых структур есть `reflect.DeepEqual`, но он медленный и в рабочем коде чаще пишут свой метод `Equal`. В тестах используют `reflect.DeepEqual` или `cmp.Diff` из `github.com/google/go-cmp`.

::: hood Выравнивание полей
Поля лежат в памяти по порядку объявления, а каждое поле выровнено по своему размеру: `int64` начинается с адреса, кратного 8, `int32` кратного 4. Между полями компилятор вставляет пустые байты (padding).

```go
type Bad struct {
	A bool  // 1 байт + 7 байт дыры
	B int64 // 8
	C bool  // 1 + 3 байта дыры
	D int32 // 4
}           // unsafe.Sizeof = 24

type Good struct {
	B int64 // 8
	D int32 // 4
	A bool  // 1
	C bool  // 1 + 2 байта до кратности 8
}           // unsafe.Sizeof = 16
```

```text
Bad:  [A . . . . . . .][B B B B B B B B][C . . . D D D D]   24 байта
Good: [B B B B B B B B][D D D D A C . .]                    16 байт
```

Проверено на Go 1.27.3 (arm64). Для одной структуры разница не важна, для слайса из миллиона это 8 МБ. Правило: поля от больших к маленьким. Анализатор `fieldalignment` из `golang.org/x/tools` находит такие структуры автоматически. Подробнее про память поговорим в модуле про рантайм.
:::

## Пустая структура

`struct{}` не содержит полей и занимает **0 байт**. Все переменные нулевого размера рантайм может разместить по одному адресу (`runtime.zerobase`), поэтому `make([]struct{}, 1_000_000)` не выделяет память под элементы.

Где применяется:

```go
set := map[string]struct{}{}            // множество: значения без памяти
done := make(chan struct{})             // сигнал «готово», данных нет
type noCopy struct{}                    // маркер-поле для анализаторов
```

Спецификация разрешает указателям на разные переменные нулевого размера быть как равными, так и неравными. Сравнение компилируется, но полагаться на его результат нельзя.

## Теги структур

Тег это строковый литерал после типа поля. Сам язык его не интерпретирует, теги читают библиотеки через `reflect`: `encoding/json`, валидаторы, ORM, драйверы БД.

```go
type User struct {
	ID       int    `json:"id"`
	Name     string `json:"name"`
	Email    string `json:"email,omitempty"`
	Password string `json:"-"`
	age      int
}

u := User{ID: 1, Name: "Аня", Password: "secret", age: 30}
b, _ := json.Marshal(u)
fmt.Println(string(b)) // {"id":1,"name":"Аня"}
```

Разбор по полям:

- `json:"id"`: имя ключа в JSON.
- `omitempty`: пропустить поле, если значение «пустое» (`0`, `""`, `nil`, пустой слайс или мапа). Для структуры не срабатывает никогда.
- `omitzero` (Go 1.24): пропустить, если значение нулевое для своего типа или если метод `IsZero()` вернул `true`. Работает и для структур, и для `time.Time`, поэтому понятнее, чем `omitempty`.
- `json:"-"`: поле никогда не участвует в JSON. Пароли, внутренние коды.
- Неэкспортированные поля (`age`) `encoding/json` не видит вообще, тег им не поможет: пакет `json` снаружи, а `reflect` не даёт ему доступа к закрытым полям.

Синтаксис тега строгий: `key:"value"`, пары через пробел, без пробелов вокруг двоеточия. Опечатку вроде `json: "id"` компилятор пропустит, а `go vet` найдёт (анализатор `structtag`).

```go
f, _ := reflect.TypeOf(User{}).FieldByName("Email")
fmt.Println(f.Tag.Get("json")) // email,omitempty
```

При разборе JSON (`json.Unmarshal`) имена ключей сопоставляются с полями **без учёта регистра**: ключ `"NAME"` попадёт в поле с тегом `name`. В Go 1.27 появился пакет `encoding/json/v2` с более строгими умолчаниями (например, он отвергает повторяющиеся имена в объекте), а старый `encoding/json` теперь работает поверх новой реализации, сохранив поведение. В курсе пока используем привычный `encoding/json`.

::: trap Поле с маленькой буквы молча пропадает из JSON
```go
// Плохо: поля не экспортированы, json их не видит
type Event struct {
	id   int    `json:"id"`   // go vet: struct field id has json tag but is not exported
	name string `json:"name"`
}
b, _ := json.Marshal(Event{1, "старт"})
fmt.Println(string(b)) // {}

// Хорошо
type Event struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}
```

Ошибки нет, просто пустой объект. Именно такие баги потом ищут по часу. Хорошо, что `go vet` замечает тег на неэкспортированном поле.
:::

## Методы

Метод это функция с **получателем** (receiver), записанным перед именем:

```go
type Rect struct{ W, H float64 }

func (r Rect) Area() float64 { // получатель-значение
	return r.W * r.H
}

func (r *Rect) Scale(k float64) { // получатель-указатель
	r.W *= k
	r.H *= k
}

r := Rect{W: 2, H: 3}
r.Scale(2)            // Go сам возьмёт адрес: (&r).Scale(2)
fmt.Println(r.Area()) // 24
```

Метод это просто синтаксис над функцией, получатель это первый аргумент. `r.Area()` это то же, что `Rect.Area(r)`, а `r.Scale(2)` то же, что `(*Rect).Scale(&r, 2)`. Отсюда всё поведение: получатель-значение это **копия**, как любой аргумент.

Методы можно объявлять для любого **своего** именованного типа, не только для структур, но только в том же пакете, где объявлен тип:

```go
type Celsius float64

func (c Celsius) Fahrenheit() float64 { return float64(c)*9/5 + 32 }
```

С Go 1.27 метод может иметь **собственные параметры типа** (generic methods), например `func (b Box) Map[T any](f func(int) T) []T`. Дженерики разберём в модуле 02.

### Value или pointer receiver

```go
type Counter struct{ n int }

func (c Counter) IncVal()  { c.n++ } // увеличит копию
func (c *Counter) IncPtr() { c.n++ } // увеличит сам счётчик

c := Counter{}
c.IncVal()
c.IncPtr()
c.IncPtr()
fmt.Println(c.n)
```

<Predict :options="['3', '2', '0', '1']" :correct="1">

`IncVal` получил копию и увеличил её, оригинал не изменился. Два вызова `IncPtr` получили адрес `c` и увеличили настоящий счётчик. Итог 2. Компилятор при этом молчит: изменение копии это валидный код, его ловит только линтер staticcheck или тест.

</Predict>

Как выбирать, по порядку проверок:

1. **Метод меняет получателя?** Указатель. Без вариантов.
2. **В структуре есть поле, которое нельзя копировать** (`sync.Mutex`, `strings.Builder`)? Указатель.
3. **Структура большая** (условно больше нескольких машинных слов)? Указатель, чтобы не копировать её на каждый вызов.
4. **Маленький неизменяемый тип** (`time.Time`, `Point`, `Celsius`)? Значение: копия дешёвая, а код безопаснее, потому что метод не может ничего испортить.
5. **Не смешивай.** Если у типа хотя бы один метод с указателем, делай указателем все. Это рекомендация из Go Code Review Comments и FAQ: смешанные наборы запутывают и создают сюрпризы с интерфейсами.

::: trap Мьютекс в структуре с получателем-значением
```go
type SafeCounter struct {
	mu sync.Mutex
	n  int
}

// Плохо: каждый вызов блокирует КОПИЮ мьютекса, защиты нет
func (c SafeCounter) Get() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.n
}
// go vet: Get passes lock by value: SafeCounter contains sync.Mutex

// Хорошо
func (c *SafeCounter) Get() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.n
}
```

Анализатор `copylocks` в `go vet` находит копирование мьютексов, но только если ты запускаешь сам `go vet`. `go test` гоняет лишь небольшое подмножество проверок vet (`printf`, `stringintconv` и ещё несколько, список в `go help test`), и `copylocks` в него не входит. Поэтому `go vet ./...` держи в CI отдельным шагом.
:::

### Автоматические & и *

Go сам подставляет `&` и `*` при вызове метода, если может:

- метод с получателем `T` можно вызвать у `*T`: Go разыменует указатель;
- метод с получателем `*T` можно вызвать у **адресуемого** значения `T`: Go возьмёт адрес.

Адресуемы переменные, поля адресуемых структур, элементы слайсов. **Не** адресуемы элементы мап, результаты функций, литералы:

```go
m := map[string]Counter{}
m["a"].IncPtr()      // ошибка компиляции: cannot call pointer method IncPtr on Counter
Counter{}.IncPtr()   // та же ошибка: у литерала нет адреса
```

## Method set: какие методы есть у типа

**Набор методов** (method set) определяет, какие интерфейсы реализует тип. Правило из спецификации:

| Тип | Входят методы с получателем |
|---|---|
| `T` | только `T` |
| `*T` | и `T`, и `*T` |

Автоматическое `&` при вызове работает для переменных, но **не** при проверке интерфейса. Значение, лежащее в интерфейсе, неадресуемо, поэтому у `T` нет методов с получателем `*T`.

```go
type Namer interface{ Name() string }

type T struct{}

func (t *T) Name() string { return "T" }

var n Namer = &T{} // ок: у *T есть Name
var m Namer = T{}  // ошибка компиляции:
// cannot use T{} (value of struct type T) as Namer value in variable declaration:
// T does not implement Namer (method Name has pointer receiver)
```

Интерфейсы подробно будут в модуле 02, а здесь запомни формулу для собеса: «у значения нет методов указателя, потому что значение в интерфейсе нельзя адресовать, а изменения копии потерялись бы».

::: hood Почему у *T есть методы T, а не наоборот
Для вызова метода с получателем `T` через указатель достаточно скопировать значение по адресу: это всегда возможно. Компилятор даже генерирует обёртку `(*T).Method`, которая делает `*p` и вызывает исходный метод.

Обратная обёртка для `T` невозможна в общем случае: нужно было бы взять адрес значения. Внутри интерфейса лежит копия, и метод с указателем изменял бы эту копию, а не то, что ты положил. Язык запрещает эту ситуацию на этапе компиляции, вместо того чтобы молча терять изменения.
:::

### Значение метода фиксирует получателя

Выражение `c.Show` без скобок это **значение метода**: функция с уже привязанным получателем. Получатель-значение копируется в момент вычисления выражения:

```go
type Counter struct{ n int }

func (c Counter) Show() { fmt.Println(c.n) }

c := Counter{1}
f := c.Show
c.n = 2
f() // 1: f держит копию c, сделанную при f := c.Show
```

Это пригодится с `defer` и горутинами: `defer c.Show()` тоже вычисляет получателя сразу.

## Встраивание: композиция вместо наследования

Если указать в структуре тип без имени поля, он **встраивается** (embedding). Поля и методы встроенного типа **продвигаются** (promoted): к ним можно обращаться напрямую.

```go
type Base struct{ ID int }

func (b Base) Describe() string { return fmt.Sprintf("Base(%d)", b.ID) }
func (b *Base) SetID(id int)    { b.ID = id }

type Post struct {
	Base  // встроенное поле, его имя совпадает с именем типа: Base
	Title string
}

p := Post{Base: Base{ID: 7}, Title: "x"}
p.SetID(8)                         // то же, что p.Base.SetID(8)
fmt.Println(p.ID, p.Describe())    // 8 Base(8)
```

Это **не наследование**. `Post` не является `Base`: передать `Post` туда, где ждут `Base`, нельзя. Это просто поле с синтаксическим сахаром для доступа. И главное отличие от классов: **нет виртуальных методов**.

```go
type Animal struct{}

func (Animal) Sound() string   { return "..." }
func (a Animal) Speak() string { return a.Sound() }

type Dog struct{ Animal }

func (Dog) Sound() string { return "Гав" }

fmt.Println(Dog{}.Speak())
```

<Predict :options="['Гав', '...', 'ошибка компиляции: два метода Sound', 'паника']" :correct="1">

`Dog{}.Speak()` продвигается в `Dog{}.Animal.Speak()`. Внутри `Speak` получатель имеет тип `Animal` и ничего не знает про `Dog`, поэтому `a.Sound()` вызывает `Animal.Sound`. В Java или TypeScript переопределённый метод вызвался бы через `this` и вывел бы «Гав». В Go полиморфизм делают через интерфейсы, а не через встраивание.

</Predict>

### Правила продвижения

- Поле или метод внешней структуры **затеняет** встроенное с тем же именем. До затенённого можно добраться явно: `s.Logger.prefix`.
- Если одно имя приходит из двух встроенных типов на одной глубине, обращение по короткому имени не компилируется: `ambiguous selector c.ID`. Сама структура при этом объявляется нормально.
- Встраивать можно указатель (`*Base`): тогда нулевое значение внешней структуры содержит `nil`, и обращение к продвинутому полю паникует.
- Можно встраивать интерфейс в структуру (часто в тестах, чтобы реализовать «половину» интерфейса) и интерфейс в интерфейс (`io.ReadWriter` это `Reader` + `Writer`).

```go
type Logger struct{ prefix string }

func (l Logger) Log(s string) { fmt.Println(l.prefix + s) }

type Service struct {
	Logger
	prefix string // затеняет Logger.prefix
}

sv := Service{Logger{"[log] "}, "svc"}
sv.Log("hi")           // [log] hi: Log работает со своим получателем Logger
fmt.Println(sv.prefix) // svc
```

### Встраивание и JSON

`encoding/json` **разворачивает** поля встроенной структуры на верхний уровень объекта. Это удобно для общих полей вроде времени создания:

```go
type Timestamps struct {
	CreatedAt time.Time `json:"created_at"`
	UpdatedAt time.Time `json:"updated_at"`
}

type Article struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
	Timestamps
}
// {"id":1,"title":"...","created_at":"...","updated_at":"..."}
```

Если дать встроенному полю тег с именем, например `json:"ts"`, оно станет вложенным объектом `"ts": {...}`.

### Литералы с продвинутыми полями (Go 1.27)

До Go 1.27 в литерале нельзя было писать продвинутое поле напрямую: только `Post{Base: Base{ID: 7}}`. С Go 1.27 ключом в литерале структуры может быть любой корректный селектор поля:

```go
p := Post{ID: 7, Title: "x"} // Go 1.27+: ID продвигается из Base
fmt.Println(p)               // {{7} x}
```

Проверено на Go 1.27.3. В коде, который должен собираться старыми версиями, этот синтаксис не скомпилируется, а в статьях ты его пока почти не встретишь.

::: trap range по слайсу структур меняет копии
```go
type Counter struct{ n int }

func (c *Counter) Inc() { c.n++ }

cs := []Counter{{}, {}}

// Плохо: cc это копия элемента, Inc увеличивает копию
for _, cc := range cs {
	cc.Inc()
}
fmt.Println(cs) // [{0} {0}]

// Хорошо: адресуем элемент слайса по индексу
for i := range cs {
	cs[i].Inc()
}
fmt.Println(cs) // [{1} {1}]
```

Та же ошибка с полями: `for _, u := range users { u.Active = true }` ничего не меняет. Для слайсов больших структур, которые часто меняют, иногда хранят `[]*User`, но это лишняя косвенность и нагрузка на GC: сначала попробуй индексы.
:::

## Конструкторы и полезное нулевое значение

Конструкторов в языке нет, есть соглашение: функция `NewT(...)`, которая возвращает `T` или `*T` в валидном состоянии.

```go
func NewServer(addr string, timeout time.Duration) *Server {
	if timeout == 0 {
		timeout = 30 * time.Second
	}
	return &Server{addr: addr, timeout: timeout, routes: make(map[string]Handler)}
}
```

Но ещё больше в Go ценят типы, которым конструктор **не нужен**: их нулевое значение сразу готово к работе. `var mu sync.Mutex`, `var b bytes.Buffer`, `var sb strings.Builder` работают без инициализации. Добиваются этого просто: поля, у которых нулевое значение осмысленно (nil-слайс годится для `append`), и ленивая инициализация мап внутри методов. Задача про стек в домашке как раз про это, и в мини-проекте `var l Ledger` должно работать.

Возвращать `T` или `*T`? Указатель, если у типа методы с указателем, если он большой или если важна идентичность объекта (один сервер, одно соединение). Значение, если тип маленький и неизменяемый (`time.Time`, `Point`).

## Что выведет программа?

```go
cs := []Counter{{}, {}}
for _, c := range cs {
	c.IncPtr()
}
fmt.Println(cs)
```

<Predict :options="['[{1} {1}]', '[{0} {0}]', 'ошибка компиляции: IncPtr требует указатель', '[{0} {1}]']" :correct="1">

`c` это локальная переменная цикла, копия элемента. Она адресуема, поэтому `c.IncPtr()` компилируется как `(&c).IncPtr()` и увеличивает копию. Элементы слайса не меняются. Правильно: `cs[i].IncPtr()`.

</Predict>

```go
type User struct {
	ID       int    `json:"id"`
	Name     string `json:"name"`
	Email    string `json:"email,omitempty"`
	Password string `json:"-"`
	age      int
}

b, _ := json.Marshal(User{ID: 1, Name: "Аня", Password: "secret", age: 30})
fmt.Println(string(b))
```

<Predict :options="['{\'id\':1,\'name\':\'Аня\',\'email\':\'\',\'age\':30}', '{\'id\':1,\'name\':\'Аня\'}', '{\'id\':1,\'name\':\'Аня\',\'Password\':\'secret\'}', '{\'ID\':1,\'Name\':\'Аня\'}']" :correct="1">

Варианты показаны с одинарными кавычками вместо двойных. `Email` пустой и помечен `omitempty`, поэтому пропущен. `Password` с тегом `-` не сериализуется никогда. `age` не экспортировано, `encoding/json` его не видит. Остаются `{"id":1,"name":"Аня"}`.

</Predict>

```go
type Base struct{ ID int }

func (b *Base) SetID(id int) { b.ID = id }

type Post struct {
	Base
	Title string
}

p := Post{Title: "x"}
q := p
q.SetID(5)
fmt.Println(p.ID, q.ID)
```

<Predict :options="['5 5', '0 5', '0 0', 'ошибка компиляции']" :correct="1">

`q := p` копирует структуру целиком, включая встроенную `Base`: это поле-значение, а не указатель. `q.SetID(5)` меняет `q.Base.ID`, а у `p` своя копия `Base`. Если бы встроен был `*Base`, обе структуры делили бы один `Base`, и вывод был бы `5 5` (а у нулевой `Post` вызов `SetID` упал бы на nil-указателе).

</Predict>

<details><summary>Чем value receiver отличается от pointer receiver? Как выбрать?</summary>

Получатель-значение получает копию, изменения не видны снаружи, зато метод безопасен и работает у любых значений. Получатель-указатель получает адрес и может менять объект, не копирует большую структуру. Указатель нужен, если метод меняет состояние, если внутри мьютекс или другой некопируемый тип, если структура большая. Значение для маленьких неизменяемых типов (`time.Time`, точки, деньги). Смешивать в одном типе не рекомендуется: если хоть один метод с указателем, делают все с указателем.

</details>
<details><summary>Что такое method set? Почему T не реализует интерфейс, если метод объявлен на *T?</summary>

Набор методов типа определяет, какие интерфейсы он реализует. У `T` только методы с получателем `T`, у `*T` методы и с `T`, и с `*T`. Значение внутри интерфейса неадресуемо, поэтому вызвать на нём метод с указателем нельзя (и изменения копии потерялись бы). Компилятор сообщает: `method Name has pointer receiver`. Решение: класть в интерфейс указатель `&T{}`.

</details>
<details><summary>Встраивание это наследование?</summary>

Нет, это композиция с синтаксическим сахаром. Встроенный тип это обычное поле с именем типа, его поля и методы продвигаются во внешнюю структуру. Но внешний тип не является встроенным (подставить его вместо встроенного нельзя), и нет виртуальной диспетчеризации: метод встроенного типа, вызывающий другой метод, всегда вызывает метод встроенного типа, даже если внешний тип объявил метод с тем же именем. Полиморфизм в Go делается интерфейсами.

</details>
<details><summary>Какие структуры можно сравнивать через ==? Можно ли сделать структуру ключом мапы?</summary>

Те, у которых все поля сравнимы. Слайс, мапа или функция в полях делают структуру несравнимой, `==` не компилируется. Сравнимая структура годится в ключ мапы, это идиоматичный составной ключ. Указатели внутри сравниваются по адресу, а не по содержимому.

</details>
<details><summary>Зачем нужна пустая структура struct{}?</summary>

Она занимает 0 байт. Используется как значение в множествах `map[T]struct{}`, как тип сигнальных каналов `chan struct{}`, как тип-маркер для методов без состояния. Все переменные нулевого размера могут иметь один адрес, поэтому на результат сравнения указателей на них полагаться нельзя: спецификация разрешает и равенство, и неравенство.

</details>
<details><summary>Что такое теги структур и как их использует encoding/json?</summary>

Строковые метаданные поля, которые читают библиотеки через `reflect`. Для JSON: имя ключа, `omitempty` (пропуск пустых значений), `omitzero` (Go 1.24, пропуск нулевых, в том числе структур и `time.Time`), `-` (никогда не сериализовать), `string` (число как строка). Неэкспортированные поля `json` не видит вообще. При `Unmarshal` ключи сопоставляются без учёта регистра. Синтаксис тега проверяет `go vet`.

</details>
<details><summary>Почему порядок полей влияет на размер структуры?</summary>

Каждое поле выравнивается по своему размеру, между полями появляются пустые байты, а размер структуры кратен самому строгому выравниванию поля. `bool, int64, bool, int32` занимает 24 байта, а те же поля от большего к меньшему 16. Анализатор `fieldalignment` подсказывает оптимальный порядок.

</details>
<details><summary>Почему нельзя копировать структуру с sync.Mutex?</summary>

Мьютекс это состояние (захвачен, кто ждёт). Копия захваченного мьютекса тоже окажется захвачена, а блокировка копии не защищает оригинал. Поэтому методы таких структур делают с получателем-указателем, а структуры передают по указателю. `go vet` (анализатор `copylocks`) ловит копирование.

</details>
:::

### Часть 1: ядро

Прочитай комментарии в `ledger.go`, они и есть ТЗ. Коротко о том, что нужно реализовать:

| Метод | Что делает |
|---|---|
| `(*Ledger).Add` | добавить расход, выдать ID, проверить сумму и категорию |
| `(*Ledger).Remove` | удалить по ID, `ErrNotFound`, если нет |
| `(*Ledger).List` | копия всех расходов, отсортированная по дате и ID |
| `(*Ledger).TotalsByCategory` | суммы по категориям |
| `(*Ledger).TotalsByMonth` | суммы по месяцам `"2026-11"` |
| `Encode`, `Decode` | JSON туда и обратно с проверкой целостности |

Ключевые решения, которые уже приняты за тебя и которые стоит понять:

- **Деньги в копейках, `int64`.** `float64` для денег не годится: `0.1 + 0.2` не равно `0.3`, а округления накапливаются в отчётах.
- **ID не переиспользуются.** После удаления расхода №5 следующий получит №6, иначе ссылки на старые ID (в логах, в истории команд) начнут указывать на другие записи. Поэтому в файле хранится `last_id`.
- **`List` отдаёт копию.** Иначе вызывающий код сможет изменить журнал в обход методов, вспомни алиасинг из урока про слайсы.
- **Ошибки как значения.** `ErrInvalidAmount` и другие объявлены через `errors.New`, сравниваются через `errors.Is`. Обёртка `fmt.Errorf("%w: ...", ErrCorrupt)` сохраняет возможность такого сравнения. Подробно ошибки разберём в модуле 02, здесь этого достаточно.
- **`Decode` не доверяет файлу.** Файл мог отредактировать человек: проверяй `last_id`, дубликаты ID, суммы и категории, а категории нормализуй так же, как в `Add`, иначе ` Еда ` из файла станет отдельной строкой отчёта.
