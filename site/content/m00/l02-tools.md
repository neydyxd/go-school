# Установка и инструменты Go

У Go одна из лучших «коробок с инструментами» среди языков: компилятор, менеджер зависимостей, форматтер, линтер, тесты, профайлер и документация живут в одной команде `go`. Не нужно выбирать между пятью сборщиками и тремя менеджерами пакетов, как в мире JavaScript. Зато нужно понимать, что делает каждая подкоманда, иначе на собесе вопрос «чем `go build` отличается от `go install`» застанет врасплох.

В этом уроке ставим Go, разбираемся с модулями и проходим по командам, которыми будешь пользоваться каждый день.

## Установка и проверка

На macOS проще всего через Homebrew:

```bash
brew install go
go version
# go version go1.27.3 darwin/arm64
```

Альтернатива: установщик с [go.dev/dl](https://go.dev/dl/). Обновлять Go часто не придётся вручную: с версии 1.21 команда `go` умеет сама скачать нужный тулчейн (об этом ниже).

Посмотри, где Go хранит своё:

```bash
go env GOROOT GOPATH GOBIN GOMODCACHE
```

- **GOROOT**: куда установлен сам Go (компилятор и стандартная библиотека). Трогать не нужно.
- **GOPATH**: по умолчанию `~/go`. Сейчас это просто «домашняя папка Go»: там лежит кеш модулей (`~/go/pkg/mod`) и бинарники, поставленные через `go install` (`~/go/bin`).
- **GOBIN**: куда `go install` кладёт бинарники. Если пусто, то `$GOPATH/bin`.

Добавь `~/go/bin` в `PATH`, иначе поставленные утилиты не найдутся:

```bash
echo 'export PATH="$PATH:$HOME/go/bin"' >> ~/.zshrc && source ~/.zshrc
```

::: trap GOPATH из старых статей
В статьях до 2019 года пишут, что код обязан лежать в `$GOPATH/src/github.com/...`. Это эпоха до модулей. Сейчас проект может лежать где угодно, главное, чтобы в его корне был `go.mod`. Если туториал просит положить код в GOPATH, он устарел.
:::

## Первая программа и модуль

```bash
mkdir hello && cd hello
go mod init example.com/hello
```

`go mod init` создаёт `go.mod`, паспорт модуля:

```go
module example.com/hello

go 1.27.3
```

- `module` задаёт **путь модуля**: префикс, по которому другие будут импортировать твои пакеты. Для своих проектов обычно `github.com/<ник>/<репо>`; домен не обязан существовать, пока модуль никто не скачивает.
- `go` задаёт **минимальную версию Go**, которую требует модуль. С 1.21 это жёсткое требование: старый тулчейн откажется собирать модуль или скачает новый.

Теперь `main.go`:

```go
package main

import "fmt"

func main() {
	fmt.Println("Привет, Go!")
}
```

```bash
go run .
# Привет, Go!
```

Три обязательных вещи исполняемой программы: пакет называется `main`, в нём есть функция `main` без аргументов и результатов, и всё это лежит в одном каталоге.

### Строгость компилятора

Go отказывается компилировать код с неиспользуемыми переменными и импортами. Это не придирка, а решение авторов языка: мёртвый импорт замедляет сборку и тянет лишние зависимости, а неиспользуемая переменная почти всегда означает баг.

```go
package main

func main() {
	x := 1
}
```

<Predict :options="['ничего не выведет', 'ошибка компиляции', 'выведет 1', 'паника во время выполнения']" :correct="1">

Компилятор остановится с ошибкой `declared and not used: x`. Неиспользуемый импорт даёт похожую ошибку: `"os" imported and not used`. Временно «заглушить» переменную можно присваиванием в пустой идентификатор: `_ = x`.

</Predict>

## Модули и зависимости

Добавим внешнюю зависимость:

```bash
go get github.com/google/uuid@latest
```

В `go.mod` появится строка `require github.com/google/uuid v1.6.0`, а рядом файл `go.sum`.

::: hood Что происходит при go get
1. Команда идёт не на GitHub напрямую, а в **модульный прокси** (`GOPROXY`, по умолчанию `https://proxy.golang.org,direct`). Прокси кеширует версии навсегда, поэтому удалённый автором тег не сломает твою сборку.
2. Скачанный архив сверяется с **базой контрольных сумм** (`GOSUMDB=sum.golang.org`). Это публичный журнал хешей: если кто-то подменит содержимое версии, хеш не совпадёт и сборка упадёт.
3. Хеши записываются в `go.sum`. Его коммитят в git вместе с `go.mod`, это гарантия, что у тебя и у CI будут байт-в-байт одинаковые зависимости.
4. Версию выбирает алгоритм **Minimal Version Selection (MVS)**. Если двум пакетам нужен `uuid` версий 1.3 и 1.5, берётся 1.5: минимальная версия, удовлетворяющая всем требованиям. Не «самая свежая из существующих», как в npm. Поэтому сборка воспроизводима без lock-файла: `go.mod` и есть lock.
:::

Команды, которые нужны постоянно:

| Команда | Что делает |
|---|---|
| `go get pkg@v1.2.3` | добавить или сменить версию зависимости |
| `go get pkg@none` | удалить зависимость |
| `go mod tidy` | привести `go.mod`/`go.sum` в соответствие с импортами: добавить недостающее, убрать лишнее |
| `go list -m all` | показать все модули сборки с версиями |
| `go mod why pkg` | объяснить, зачем модулю нужна зависимость |

::: trap go.sum не лишний файл
Новички добавляют `go.sum` в `.gitignore`, «потому что он генерируется». Не надо: без него каждый клон будет заново доверять сети, а проверка целостности теряет смысл.
:::

### Тулчейн сам себя обновляет

С Go 1.21 в `go.mod` может стоять директива `toolchain`, а переменная `GOTOOLCHAIN` по умолчанию равна `auto`. Если модуль требует `go 1.28`, а у тебя 1.27, команда `go` скачает нужную версию и запустит её. Проверить: `go env GOTOOLCHAIN`.

## Ежедневные команды

| Команда | Зачем |
|---|---|
| `go run .` | собрать во временную папку и сразу запустить |
| `go build -o bin/app .` | собрать бинарник |
| `go install pkg@latest` | собрать и положить бинарник в `GOBIN` (для утилит) |
| `go test ./...` | тесты во всех пакетах модуля |
| `go fmt ./...` | отформатировать код (обёртка над `gofmt -l -w`) |
| `go vet ./...` | статический анализ подозрительного кода |
| `go doc fmt.Println` | документация прямо в терминале |
| `go env` | настройки окружения |

`./...` означает «этот каталог и все вложенные пакеты». Встретится в каждом втором проекте.

### go build против go install

`go build` собирает бинарник в текущей папке (или туда, куда укажешь `-o`). `go install` собирает и кладёт результат в `GOBIN`, то есть «устанавливает» программу в систему. Для утилит пишут `go install golang.org/x/tools/cmd/stringer@latest`: так ставится конкретная версия, не трогая `go.mod` текущего проекта.

### Инструменты проекта в go.mod

С Go 1.24 инструменты разработки (генераторы, линтеры) можно закрепить прямо в модуле:

```bash
go get -tool golang.org/x/tools/cmd/stringer
go tool stringer -type=Color
```

В `go.mod` появится директива `tool`, и у всей команды будет одна и та же версия генератора. Раньше для этого заводили файл `tools.go` с пустыми импортами, в старых проектах ты его ещё встретишь.

### gofmt: спор, который закрыт

В Go нет споров про табы и пробелы: формат один, его задаёт `gofmt`, и его используют все. Настрой редактор форматировать при сохранении и забудь. Код, не прошедший `gofmt`, на ревью выглядит так же странно, как письмо без пробелов после запятых.

### Кросс-компиляция в одну строку

Go собирает статический бинарник под другую ОС без дополнительных инструментов:

```bash
GOOS=linux GOARCH=amd64 go build -o bin/app-linux .
GOOS=windows GOARCH=amd64 go build -o bin/app.exe .
go tool dist list   # все поддерживаемые пары ОС/архитектура
```

Именно поэтому Go любят для CLI-утилит и Docker-образов: один файл без зависимостей кладётся в `scratch`-контейнер размером в несколько мегабайт.

::: hood Почему бинарник такой большой
Hello world весит около 2 МБ. Внутри не только твой код, но и **рантайм**: планировщик горутин, сборщик мусора, аллокатор памяти. Всё линкуется статически, поэтому бинарнику не нужен установленный Go на сервере. Уменьшить можно флагами `-ldflags="-s -w"` (выбросить таблицу символов и отладочную информацию), но для учёбы это не нужно.
:::

## Что выведет программа?

```bash
# файл main.go
package hello

func main() {}
```

```bash
go run main.go
```

<Predict :options="['ничего, программа пустая', 'package command-line-arguments is not a main package', 'undefined: main', 'программа зависнет']" :correct="1">

Запускать можно только пакет `main`. Имя файла и наличие функции `main` не помогают: команда `go` смотрит на имя пакета. `command-line-arguments` здесь это имя, которое Go даёт пакету, собранному из файлов, перечисленных в командной строке.

</Predict>

::: interview
<details><summary>Что такое модуль и чем он отличается от пакета?</summary>

Пакет это каталог с `.go`-файлами с одинаковым `package`-объявлением, единица компиляции и видимости. Модуль это набор пакетов с общим `go.mod`, единица версионирования и распространения. Один модуль обычно содержит много пакетов.

</details>
<details><summary>Зачем нужен go.sum и надо ли его коммитить?</summary>

`go.sum` хранит криптографические хеши каждой версии каждой зависимости. При скачивании хеши сверяются, поэтому подмена кода в зависимости обнаружится. Коммитить обязательно: это часть воспроизводимой и безопасной сборки.

</details>
<details><summary>Как Go выбирает версию зависимости?</summary>

Minimal Version Selection: из всех требований к модулю в графе зависимостей выбирается максимальная из минимально требуемых версий. Не самая свежая из опубликованных. Результат детерминирован и не зависит от того, когда ты запускаешь сборку, поэтому отдельный lock-файл не нужен.

</details>
<details><summary>Чем go build отличается от go install? А go run?</summary>

`go build` собирает бинарник в текущий каталог или по `-o`. `go install` собирает и кладёт в `GOBIN`; с суффиксом `@version` ставит утилиту, не трогая текущий модуль. `go run` собирает во временный каталог и сразу запускает, бинарник не сохраняется.

</details>
<details><summary>Почему неиспользуемый импорт это ошибка, а не предупреждение?</summary>

Позиция авторов языка: предупреждения игнорируют, и они копятся. Лишний импорт замедляет компиляцию и добавляет зависимость, неиспользуемая переменная часто означает баг (например, затенение через `:=`). Поэтому это ошибка.

</details>
<details><summary>Что такое GOPROXY и зачем он нужен?</summary>

Адрес модульного прокси, через который `go` скачивает зависимости. По умолчанию `proxy.golang.org`. Прокси кеширует версии навсегда (защита от удалённых тегов и упавшего GitHub) и ускоряет загрузку. В компаниях ставят свой прокси, например Athens или Nexus, для приватных модулей и аудита; приватные пути исключают через `GOPRIVATE`.

</details>
<details><summary>Как собрать бинарник под Linux на маке?</summary>

`GOOS=linux GOARCH=amd64 go build`. Кросс-компиляция встроена в тулчейн, если не используется cgo. Список платформ: `go tool dist list`.

</details>
:::
