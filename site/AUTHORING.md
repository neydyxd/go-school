# Как писать уроки Go School

Контракт для авторов уроков. Читатель курса: Степан, фронтендер, который с нуля учит Go, чтобы стать бэкендером и уверенно проходить собеседования. Ему нужно «почему» и «как устроено», а не пересказ документации.

Перед работой прочитай:
1. `docs/design.md`: программа курса (какие темы входят в твои уроки) и шаблон урока.
2. `site/content/m00/l02-tools.md`: **образцовый урок**. Равняйся на него по тону, плотности и разметке.
3. `site/.vitepress/course.ts`: точные `slug` и названия уроков.

## Где лежат файлы

- Урок: `site/content/<module>/<slug>.md`, `slug` строго из `course.ts` (например `site/content/m01/l05-slices.md`). Файл появился, значит урок «открылся» в навигации.
- Домашка: `homework/<module>/<slug>/` (например `homework/m01/l05-slices/`).
- Эталоны: `homework/.solutions/<module>/<slug>/`, **те же имена файлов**, что у заготовок.

Не трогай чужие модули, `course.ts`, тему сайта, скрипты. Ничего не коммить: коммиты делает координатор.

## Шаблон урока (порядок обязателен)

1. `# Заголовок` (как в `course.ts`, можно чуть длиннее).
2. Вступление: зачем это, связь с реальной бэкенд-работой (2-3 абзаца).
3. Теория: разделы `##` и `###`, от простого к сложному, с кодом. Каждая тема из программы `docs/design.md` для этого урока должна быть раскрыта.
4. `::: hood` «Под капотом» там, где есть что показать: как устроено в рантайме/компиляторе, схемы в текстовых блоках.
5. `::: trap` «Грабли»: минимум 2 на урок, с кодом «плохо» и «хорошо».
6. `## Что выведет программа?`: 2-4 задачи через `<Predict>` (плюс 1-2 можно внутри теории).
7. `::: interview`: 6-10 вопросов с развёрнутыми ответами.
8. `## Источники`: 4-8 ссылок.
9. `## Домашка`: 3-8 заданий через `<Hw>`.

Объём: 1500-4500 слов в зависимости от темы. Сложные темы (слайсы, мапы, интерфейсы, каналы, планировщик) разжёвываются подробно: аналогия, механизм, пример, граничные случаи.

## Разметка

**Блоки:**

```md
::: hood
Текст про устройство.
:::

::: hood Свой заголовок блока
...
:::

::: trap
...
:::

::: details Эталонное решение
...
:::
```

**Вопросы собеса** (пустые строки внутри `<details>` обязательны, иначе markdown не отрендерится):

```md
::: interview
<details><summary>Вопрос?</summary>

Развёрнутый ответ, можно с `кодом` и списками.

</details>
<details><summary>Следующий вопрос?</summary>

...

</details>
:::
```

**Что выведет программа:** код отдельным блоком перед компонентом, варианты строками, `correct` это индекс с нуля. Внутри атрибута используй одинарные кавычки; если в варианте нужна одинарная кавычка, используй `\'`. Разбор в слоте, с пустыми строками вокруг.

```md
```go
fmt.Println(len("привет"))
```

<Predict :options="['6', '12', '7']" :correct="1">

Разбор: `len` считает байты, а кириллица в UTF-8 занимает 2 байта на букву.

</Predict>
```

**Домашка:**

```md
<Hw id="ex1" title="Короткое название" level="база">

Условие. Путь к файлу, команда запуска:

```bash
cd homework && go test -v ./m01/l05-slices/ -run TestAppendAll
```

</Hw>
```

`level`: `база`, `посложнее`, `со звёздочкой`. `id` уникален внутри урока (`ex1`, `ex2`...).

**Ловушки VitePress:**
- `{{` вне блоков кода Vue воспринимает как шаблон и ломает сборку. Вложенные литералы вроде `[][]int{{1, 2}}` пиши только в блоках кода ```go. Если очень нужно в тексте, оберни абзац в `<span v-pre>...</span>`.
- Ссылки на другие уроки ставь только на уже существующие файлы или уроки своей пачки, иначе сборка упадёт с dead link. Про будущие уроки пиши текстом: «разберём в модуле про конкурентность».
- Угловые скобки в тексте (`<-ch`, `[T any]`) держи внутри `кода`.

## Факты и проверка

- Целевая версия: **Go 1.27.3** (установлен локально). Изменения языка и библиотеки 1.21-1.27 сверяй с release notes в `docs/ref/go1.NN.txt` и `go doc`. Важное для собеса: переменная цикла на итерацию с 1.22, `range` по int (1.22) и по функциям (1.23), swiss-таблицы в map (1.24), `testing.B.Loop` (1.24), `sync.WaitGroup.Go` (1.25), GOMAXPROCS с учётом cgroup (1.25). Проверь каждое по release notes, прежде чем писать.
- **Каждый пример «что выведет» и каждый вывод в комментариях реально запусти** в отдельной временной папке (`d=$(mktemp -d) && cd "$d" && go mod init x`). Не пиши вывод по памяти.
- Непроверяемое не пиши. Если сомневаешься в детали рантайма, сформулируй осторожнее или найди первоисточник (исходники `$(go env GOROOT)/src/runtime`, go.dev/blog, спецификация).
- `rm -rf` запрещён хуком, используй новые `mktemp -d`.

## Источники

- 4-8 на урок, **русские первыми**, у каждого пометка `RU` или `EN` и что именно там читать.
- Каждую ссылку проверь: `curl -s -o /dev/null -w '%{http_code}' -L <url>` даёт 200 и по `<title>` страница про то, что ты обещаешь. Выдуманные или битые ссылки недопустимы.
- Хорошие кандидаты: go.dev (spec, blog, doc), pkg.go.dev, gobyexample.ru, конкретные статьи на habr.com (проверь, что статья существует и по теме), Stepik, YouTube-каналы (Николай Тузов и другие, проверенные), книги (Донован, Керниган «Язык программирования Go»; Харсаньи «100 ошибок Go»; Боднер «Learning Go») можно указывать без ссылки или со ссылкой на издательство, если проверил.

## Домашка: соглашения

- Пакет: `package lMMslug` без дефисов (`homework/m01/l05-slices/` → `package l05slices`).
- Файлы: `exK_name.go` (заготовка) + `exK_name_test.go` (тесты). Эталон `homework/.solutions/<путь>/exK_name.go` с тем же именем и тем же API.
- Заготовка компилируется: тела функций `panic("TODO: ...")` или нулевые значения; комментарий над функцией = условие задачи (что принять, что вернуть, граничные случаи).
- Тесты табличные, имена кейсов по-русски, сообщения вида `Func(%v) = %v, want %v`. Тест обязан падать на заготовке и ловить типичные неверные решения (пустой ввод, nil, границы, юникод, переполнение, порядок).
- Конкурентные задачи: тесты детерминированы, проходят с `-race -count=5`, не зависают на неверном решении (ограничивай ожидание через `time.After`/`context.WithTimeout` и падай с понятным сообщением).
- `go vet` на заготовках и эталонах чистый.
- В `Hw`-блоке урока указывай путь и команду запуска. Задания без кода (поставить, измерить, сравнить) тоже допустимы, но в каждом уроке с практикой минимум 2 задания с тестами.
- Мини-проект модуля: `homework/<module>/project-<name>/`: ядро логики с тестами (заготовка + эталон), а CLI/обвязка как ТЗ с чеклистом в уроке.

Проверки перед сдачей (все обязаны пройти):

```bash
cd homework
./scripts/check-stubs.sh ./m01/...              # exit 0: все заготовки красные, vet чистый
COUNT=5 ./scripts/check-solutions.sh ./m01/...  # exit 0: эталоны зелёные с -race
cd ../site && pnpm build                        # сборка без ошибок
grep -rn '—' <твои файлы>                       # пусто
```

## Стиль

- По-русски, на «ты», живо и конкретно. Без воды, канцелярита и «давайте рассмотрим».
- **Запрещён символ «—» (длинное тире)** во всех файлах: тексте, коде, комментариях. Перестраивай фразу: запятая, двоеточие, точка. Диапазоны через дефис: `1-3`.
- Термины на английском оставляй как есть (`slice`, `goroutine` можно и «слайс», «горутина», но единообразно внутри урока).
- Код идиоматичный, `gofmt`-нутый, табы для отступов.
- Аналогии приветствуются, если они точные. Неточная аналогия хуже никакой.
