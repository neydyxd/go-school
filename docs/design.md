# Go School: дизайн курса

Дата: 2026-11-04. Автор запроса: Степан Максимов. Статус: черновик на утверждение.

## Зачем

Степан начал учить Go и хочет вырасти с нуля до джуниор-бэкендера, который понимает язык и экосистему глубоко: что происходит под капотом, где грабли, почему так устроено. Критерий успеха: уверенно проходить технические собеседования на Go Junior (а по части тем и Middle) и иметь портфолио из рабочих сервисов.

Курс делается для себя, поэтому важнее всего полнота, глубина и практика, а не маркетинговая упаковка.

## Цели

1. Полная программа от «никогда не писал на Go» до «собираю сервис на Gin + PostgreSQL + River, покрытый тестами, в Docker».
2. Каждая сложная тема разжёвана: интуиция, затем механика, затем «под капотом», затем грабли.
3. Много практики: домашка в каждом уроке, мини-проекты в конце модулей, дипломный проект.
4. Подготовка к собесу встроена в каждый урок (блок «На собесе спросят»), плюс отдельный модуль с банком вопросов.
5. Алгоритмы и структуры данных как отдельный параллельный трек с задачами на Go.
6. Источники к каждому уроку, русские в приоритете, у каждого пометка языка.

## Не цели

- Не платформа для других людей: нет аккаунтов, бэкенда, оплаты, сертификатов.
- Не встроенный онлайн-компилятор Go в браузере. Код запускается локально, это и есть навык.
- Не полные эталонные реализации больших проектов (Gin API, River-сервис, диплом): там ТЗ, каркас, подсказки и чеклист.
- Не фронтенд, не Kubernetes, не облака глубоко. Только то, что нужно джуниор-бэкендеру.

## Анти-цели (провал, даже если формально работает)

- Поверхностный пересказ документации без «почему».
- Устаревшие факты (например, поведение переменной цикла до Go 1.22, старая реализация map до Go 1.24 без оговорки).
- Мёртвые или выдуманные ссылки на источники.
- Домашка, которую нельзя проверить, или тесты, которые проходят на пустой заглушке.
- Шаблонный «ИИшный» вид сайта.

## Ограничения и окружение

- macOS, Go 1.27.3, Node 24 + pnpm, Docker 28 (для PostgreSQL, Redis в практике).
- Курс ориентирован на актуальный Go 1.27; изменения версий 1.21 до 1.27 упоминаются там, где это важно для собеса.
- Тексты на русском. Без длинного тире «—» во всех текстах и коде.

## Подходы к сборке сайта

| Подход | Плюсы | Минусы |
|---|---|---|
| **VitePress (выбран)** | Markdown-контент, встроенный поиск, подсветка Go, тёмная тема, спойлеры `::: details`, Vue-компоненты для интерактива | Нужен Node для запуска |
| Сайт на Go (html/template + goldmark) | Символично, один язык | Поиск, навигацию, подсветку писать самому: время уходит не на контент |
| Next.js | Гибкость | Тяжело для статичного курса, лишняя сложность |

Выбор мой (Степан говорил о результате, а не о технологиях): VitePress с собственной темой.

## Формат домашки (решение Степана: гибрид)

- **Задачи с чёткой логикой** (основы, интерфейсы, конкурентность, алгоритмы, часть БД): Go-пакет с заготовкой и тестами. Заготовка компилируется и падает (`panic("TODO")` или нулевое значение), Степан доводит тесты до зелёного: `go test ./m04/...`.
- **SQL-задачи**: учебная база (docker compose + seed), формулировка и ожидаемый результат; эталонный запрос под спойлером.
- **Проектные задания** (URL-shortener, REST API на Gin, River-сервис, диплом): ТЗ на сайте, минимальный каркас, чеклист приёмки и curl-команды для проверки руками.

## Структура репозитория

```
~/Desktop/globus/go-school/
  site/                 VitePress (docs/ с уроками, .vitepress/theme)
  homework/             Go-модуль с домашками
    m01/l05-slices/     пакет урока: *.go заготовки + *_test.go
    .solutions/         эталоны, то же дерево и те же имена файлов (точка: go tool игнорирует)
    scripts/check-solutions.sh   копирует homework во временную папку, накладывает эталоны, гоняет go test
    docker-compose.yml  PostgreSQL 17 + Redis для практики
  projects/             каркасы проектных заданий
  docs/design.md        этот документ
```

Инвариант качества домашек: `go test ./...` на заготовках компилируется и падает; `scripts/check-solutions.sh` полностью зелёный; `go vet` чистый.

## Шаблон урока

1. **Зачем это** (2-3 абзаца, связь с реальной работой).
2. **Теория** с примерами кода, от простого к сложному.
3. **Под капотом** (где применимо): как устроено внутри, со схемами.
4. **Грабли**: типичные ошибки с кодом «плохо / хорошо».
5. **Что выведет программа?**: 2-4 задачки с ответом и объяснением под спойлером.
6. **На собесе спросят**: 5-10 вопросов с развёрнутыми ответами под спойлером.
7. **Источники**: 4-8 ссылок, RU первыми, у каждой пометка RU/EN и что именно там читать.
8. **Домашка**: 3-8 заданий с уровнями (база / посложнее / со звёздочкой), путь к пакету и команда запуска.
9. Отметка «урок пройден».

## Программа (13 модулей, 77 уроков)

Рекомендуемый темп: 10-12 часов в неделю, около 7-8 месяцев. Алгоритмический трек идёт параллельно, начиная со 2-го модуля: 2-3 задачи в неделю.

**00. Старт** (2)
1. Как устроен курс и как учиться (активное повторение, заметки, как сдавать домашку, git).
2. Установка и инструменты: toolchain, модули, `go run/build/fmt/vet/test`, gopls, редактор.

**01. Основы языка** (8)
1. Переменные, типы, нулевые значения, константы, iota, преобразования, переполнение.
2. Управляющие конструкции: if, for, switch, метки, range (семантика переменной цикла с 1.22, range по int и функциям).
3. Функции: несколько результатов, именованные результаты, variadic, замыкания, defer (порядок, вычисление аргументов), panic/recover.
4. Указатели: передача по значению всегда, `&`, `new`, nil.
5. Массивы и слайсы: заголовок слайса, len/cap, рост при append, алиасинг, copy, три индекса, пакет slices, утечки через подслайс.
6. Строки, байты, руны: UTF-8, range по строке, неизменяемость, strings.Builder.
7. Мапы: устройство (swiss tables с 1.24), случайный порядок, nil-мапа, не потокобезопасны, пакет maps, множество через `map[T]struct{}`.
8. Структуры и методы: теги, встраивание, value vs pointer receiver, method sets, сравнимость, пустая структура.
Мини-проект: CLI учёта расходов с хранением в JSON.

**02. Интерфейсы, ошибки, дженерики, пакеты** (6)
1. Интерфейсы: неявная реализация, маленькие интерфейсы, «принимай интерфейсы, возвращай структуры», type assertion и type switch.
2. Интерфейсы под капотом: iface/eface, itab, ловушка «nil-интерфейс не равен интерфейсу с nil-указателем».
3. Ошибки: sentinel, свои типы, `%w`, errors.Is/As/Join, panic vs error.
4. Дженерики: параметры типов, ограничения, `~`, comparable, cmp.Ordered, когда дженерики не нужны.
5. Пакеты и модули: видимость, internal, init, go.mod/go.sum, семантические версии, replace, workspaces.
6. Стандартная библиотека, которую надо знать: io.Reader/Writer, bufio, fmt, os, time (и его ловушки), strconv, encoding/json основы.
Мини-проект: утилита в духе wc/grep поверх io.Reader.

**03. Тестирование и инструменты** (4)
1. testing: табличные тесты, подтесты, t.Helper, t.Parallel, golden-файлы, testify кратко.
2. Бенчмарки (b.Loop), фаззинг, покрытие, Example-тесты.
3. Тестируемый дизайн: зависимости через интерфейсы, fake vs mock, httptest.
4. Качество: go vet, staticcheck, golangci-lint, race detector, pprof, trace.

**04. Конкурентность** (8)
1. Горутины: конкурентность vs параллелизм, WaitGroup (включая wg.Go).
2. Каналы: буфер, закрытие, range, направленные, nil-каналы, полная таблица поведения операций.
3. select: таймауты, default, неблокирующие операции, ловушки time.After.
4. sync: Mutex, RWMutex, Once/OnceValue, Cond, Pool, sync.Map, atomic.
5. context: отмена, дедлайны, values и когда их нельзя использовать.
6. Паттерны: worker pool, pipeline, fan-in/fan-out, errgroup, семафор, rate limiting.
7. Проблемы: data race vs race condition, deadlock, утечки горутин, модель памяти и happens-before.
8. Планировщик под капотом: G, M, P, work stealing, вытеснение, системные вызовы, GOMAXPROCS в контейнерах.
Мини-проект: конкурентный чекер ссылок с ограничением параллелизма и отменой.

**05. Рантайм под капотом** (3)
1. Память: стек и куча, escape analysis (`-gcflags=-m`), аллокации, выравнивание полей.
2. Сборщик мусора: трёхцветная пометка, write barrier, GOGC, GOMEMLIMIT, актуальные изменения GC.
3. Каналы и мапы изнутри (hchan, swiss map) и практика оптимизации на pprof.

**06. HTTP на стандартной библиотеке** (5)
1. Как работает веб: TCP, DNS, HTTP, REST, методы, статусы, идемпотентность, заголовки.
2. net/http сервер: Handler, ServeMux с паттернами 1.22, middleware, контекст запроса.
3. JSON API: теги, валидация ввода, единый формат ошибок.
4. http.Client: таймауты, переиспользование соединений, закрытие Body, ретраи.
5. Сервер к продакшну: graceful shutdown, таймауты сервера, slog, конфиг из env.
Проект: URL-shortener на stdlib.

**07. Базы данных** (9)
1. Зачем реляционные БД, PostgreSQL в Docker, psql.
2. SQL основы: SELECT, WHERE, ORDER BY, LIMIT, INSERT/UPDATE/DELETE, логика NULL.
3. SQL продвинутый: JOIN, GROUP BY/HAVING, подзапросы, CTE, оконные функции.
4. Проектирование схем: нормализация, ключи, связи, ограничения, типы Postgres (uuid, timestamptz, jsonb, numeric для денег).
5. Индексы: устройство B-tree, составные, покрывающие, частичные, GIN, EXPLAIN ANALYZE, почему индекс не используется.
6. Транзакции: ACID, уровни изоляции и аномалии, MVCC, блокировки, SELECT FOR UPDATE, взаимоблокировки, оптимистичная блокировка.
7. Go и БД: database/sql и pgx, пул соединений, NULL, транзакции в коде, SQL-инъекции.
8. sqlc, ORM (GORM), query builder (squirrel): компромиссы; миграции на goose.
9. Redis и кеширование: структуры, TTL, cache-aside, инвалидация, go-redis.

**08. Gin и архитектура сервиса** (7)
1. Зачем фреймворк: Gin против net/http, chi, echo, fiber; роутинг, группы, параметры.
2. Binding и валидация (validator/v10), единый формат ответов и ошибок.
3. Middleware в Gin: логирование, recovery, request ID, CORS, таймауты.
4. Архитектура: слои handler/service/repository, чистая архитектура без фанатизма, раскладка проекта, DI руками.
5. Аутентификация и безопасность: bcrypt/argon2, JWT (access/refresh), OWASP для API, rate limiting.
6. Конфиг, логирование, OpenAPI-документация, версионирование API.
7. Тестирование сервиса: httptest с Gin, юнит-тесты сервисного слоя, интеграционные тесты с testcontainers-go.
Проект: REST API «Трекер задач» (Gin + PostgreSQL + JWT + тесты).

**09. Фоновые задачи и River** (4)
1. Зачем очереди: асинхронность, ретраи, идемпотентность, at-least-once, transactional outbox, очередь в БД против брокера.
2. River основы: миграции, JobArgs, Worker, Client, Insert и InsertTx в одной транзакции с бизнес-данными.
3. River продвинутое: ретраи и backoff, snooze, отмена, уникальные задачи, периодические задачи, очереди и приоритеты, River UI, тестирование (rivertest).
4. Брокеры сообщений обзорно: Kafka и RabbitMQ (партиции, consumer groups, гарантии доставки).
Проект: email-уведомления и ежедневный дайджест в «Трекере задач» через River.

**10. Продакшн** (5)
1. Docker для Go: multi-stage, distroless/scratch, docker compose.
2. Наблюдаемость: логи, метрики Prometheus, health/readiness, обзор OpenTelemetry.
3. gRPC и protobuf: когда вместо REST, buf, unary и streaming, interceptors.
4. CI: GitHub Actions (lint, test, build), Makefile.
5. System design для джуна: монолит и микросервисы, кеш, балансировка, CAP, ретраи, circuit breaker.

**11. Алгоритмы и структуры данных** (12, параллельный трек)
1. Big-O и как решать задачу на собесе вслух.
2. Массивы: два указателя, префиксные суммы.
3. Хеш-таблицы: подсчёт, группировка.
4. Скользящее окно.
5. Стек, очередь, монотонный стек.
6. Бинарный поиск, включая поиск по ответу.
7. Связные списки.
8. Сортировки (quick, merge, counting) и slices.Sort.
9. Деревья и рекурсия: обходы, BST, обход по уровням.
10. Графы: BFS, DFS, топологическая сортировка, Дейкстра обзорно.
11. Куча (container/heap), top-K.
12. Динамическое программирование и жадные алгоритмы.
В каждом уроке 6-10 задач уровня easy/medium с тестами.

**12. Подготовка к собеседованию** (4)
1. Банк вопросов по Go (100+ с ответами) в режиме карточек.
2. «Что выведет код» и live-coding по конкурентности.
3. Вопросы по БД, сетям, архитектуре; system design на уровне джуна.
4. Резюме, pet-проекты, как вести себя на собесе, поведенческие вопросы.
Дипломный проект: сервис на выбор из 3 тем, со всем стеком курса.

## Фишки сайта

- Главная: карта роадмапа (модули как маршрут), общий прогресс, «продолжить с того места».
- Прогресс уроков и домашек в localStorage.
- Блоки «Под капотом», «Грабли», «На собесе спросят» визуально различимы.
- Интерактивный блок «Что выведет программа?»: сначала свой ответ, потом раскрытие.
- Страница карточек для собеса: случайный порядок, «знаю / повторить», повтор слабых.
- Встроенный полнотекстовый поиск.

## Порядок выпуска и контроль качества (мои решения)

- **Волнами, а не одним проходом.** Волна 1: сайт целиком (тема, карта, прогресс, компоненты) и модули 00-04 + первые уроки алгоритмов, чтобы учиться можно было сразу. Волна 2: модули 05-08. Волна 3: 09-12 и диплом. Каждая волна полностью проверена до перехода к следующей.
- **Актуальность фактов.** Исполнители сверяются с локальным `go doc` (Go 1.27.3), release notes go.dev/doc/go1.N и официальной документацией библиотек (River, Gin, pgx, testcontainers) через веб. Версии библиотек фиксируются в go.mod по факту установки. Непроверяемое не пишем.
- **Ссылки.** Скрипт `site/scripts/check-links.mjs` проверяет все внешние ссылки на живость; битые убираются до сдачи волны.
- **Сила тестов.** Тест обязан падать на заготовке. Для задач с подвохом (граничные случаи, конкурентность) ревьюер проверяет, что тест ловит типичное неверное решение; конкурентные задачи гоняются с `-race`.
- **Проекты.** Полного эталона нет, но каркас обязан компилироваться, а каждый пункт чеклиста проверен на выполнимость.
- **Алгоритмы.** Условия пишем своими словами (классические задачи), со ссылкой на аналог на LeetCode для дополнительной практики.
- **Прогресс.** localStorage со схемой версии + экспорт/импорт в JSON-файл (защита от потери за 8 месяцев).
- **Запуск.** Только локально: `pnpm dev` в `site/`. Деплой не делаем, пока не понадобится.
- **Темы.** Светлая и тёмная обязательны.
