# Go School, волна 2: план реализации

**Goal:** Модули 05-08 (24 урока) с домашкой: рантайм, HTTP на stdlib, PostgreSQL и Redis, Gin и архитектура сервиса.

**Spec:** `docs/design.md`. Процесс тот же, что в волне 1 (`docs/plans/2026-11-04-wave1.md`): параллельные авторы по контракту `site/AUTHORING.md`, ревью с подстановкой неверных решений, исправления, точечная перепроверка, коммит пачки.

## Global Constraints

Все из волны 1, плюс:
- База для практики: `homework/docker-compose.yml`, PostgreSQL 17 на `localhost:55432`, Redis 7 на `localhost:56379` (нестандартные порты, чтобы не конфликтовать с локальными установками).
- Тесты с БД используют общий хелпер `goschool/homework/internal/testdb` (изолированная схема на тест) и `internal/testredis` (уникальный префикс ключей). База недоступна: тест **падает** с подсказкой `docker compose up -d`, а не пропускается.
- Зависимости уже в `homework/go.mod` (pgx/v5, gin, validator/v10, go-redis/v9, goose/v3, golang-jwt/v5, x/crypto, x/time). Новую добавлять только при реальной нужде одним `go get`.
- SQL-домашка: файл `qNN_name.sql` (заготовка `-- TODO`) + Go-тест, который выполняет файл на сиде урока и сравнивает строки с ожидаемыми. Эталонный `.sql` в `.solutions/`.
- Сквозной проект «Трекер задач» (Gin + PostgreSQL + JWT) живёт в `projects/tasktracker/` отдельным Go-модулем: каркас компилируется, ТЗ и чеклист в уроке m08/l07. В волне 3 к нему добавится River.

## Review Focus

1. База не поднята: тест падает с понятной подсказкой, а не висит и не пропускается.
2. Параллельные пакеты с БД не мешают друг другу (изоляция схем и ключей Redis).
3. SQL-задача: запрос с верным результатом, но другим порядком строк, проходит, если порядок не входит в условие; и падает, если входит.
4. Тесты транзакций и блокировок детерминированы (без sleep-гонок).
5. Каркас трекера компилируется, чеклист выполним.
