# Go School, волна 3: план реализации

**Goal:** Модули 09-12 и дипломный проект: River, продакшн, вторая половина алгоритмов, подготовка к собесу с карточками.

**Spec:** `docs/design.md`. Процесс как в волнах 1-2: параллельные авторы по контракту `site/AUTHORING.md`, ревью с подстановкой неверных решений, исправления тем же автором, точечная перепроверка, коммит пачки.

## Global Constraints

Все из волн 1-2, плюс:
- Зависимости уже в `homework/go.mod` (координатор добавил заранее): River v0.51.0 (`river`, `riverdriver/riverpgxv5`, `rivermigrate`, `rivertest`, `rivertype`), `google.golang.org/grpc` v1.85.0, `google.golang.org/protobuf` v1.36.12, `prometheus/client_golang` v1.25.0.
- gRPC: сгенерированные `*.pb.go` коммитятся рядом с `.proto`, чтобы студенту для `go test` не нужен был protoc. Генераторы автор ставит через `go install` (buf, protoc-gen-go, protoc-gen-go-grpc), команду генерации пишет в урок. Тесты через `bufconn`, без сетевых портов.
- River в тестах: таблицы River мигрируются в схему теста (`rivermigrate` на пуле из `testdb`), проверки через `rivertest`. Без `time.Sleep`-ожиданий.
- Алгоритмы: условия своими словами, ссылка на аналог LeetCode, 6-10 задач на урок, тесты ловят типичные неверные решения (пустой ввод, один элемент, дубликаты, переполнение, худший случай по времени через большой ввод с таймаутом).
- Карточки собеса: компонент `Flashcards.vue` в теме, данные в JSON рядом с уроком, состояние в localStorage под отдельным ключом `go-school:cards` (схема прогресса уроков не меняется), логика в чистых функциях с vitest-тестами.
- Диплом: страница `site/content/diploma.md`, три темы на выбор, у каждой ТЗ, этапы и чеклист; общий компилируемый каркас `projects/diploma/` (отдельный Go-модуль).

## Review Focus

1. River: задача вставлена в той же транзакции, что и бизнес-данные; откат транзакции не оставляет задачу.
2. gRPC-тесты не открывают реальные порты и не зависают при неверном решении.
3. Алгоритмы: решение за O(n²) там, где требуется O(n log n), ловится тестом с большим вводом и таймаутом.
4. Карточки: состояние переживает перезагрузку, повреждённый localStorage не ломает страницу.
5. Каркасы проектов компилируются, чеклисты выполнимы.
